# Deployment notes

This backend has not been deployed or connected to a live database or object-storage account. Verify the host's current plan, quotas, outbound networking, persistent filesystem behavior, and environment-variable support before selecting it. Do not enable paid resources without approval.

Use MongoDB Atlas with a least-privilege database user, restricted network access, and backups. For object storage, select either a private S3-compatible bucket or Cloudinary authenticated assets; do not use local disk for production documents. S3 uploads use temporary objects under `pending/`, copied into `applications/{application_id}/` after confirmation. Add a lifecycle rule to delete abandoned S3 pending objects after one day.

Set `APP_ENV=production`, `MONGODB_URI`, `MONGODB_DATABASE`, `JWT_SECRET_KEY` (random and at least 32 characters), exact `FRONTEND_ORIGINS`, and `COOKIE_SECURE=true`. For S3-compatible storage set `STORAGE_PROVIDER=s3`, `STORAGE_BUCKET`, and any required region/endpoint settings; provide both `STORAGE_ACCESS_KEY_ID` and `STORAGE_SECRET_ACCESS_KEY`, or use the host's IAM role. Alternatively, set `STORAGE_PROVIDER=cloudinary` and all three `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` values. Keep these Cloudinary credentials in the backend's host secret manager; never place them in frontend configuration. Documents and profile photos are uploaded as authenticated Cloudinary assets; the backend issues signed URLs that expire after five minutes only after request authorization. Cloudinary account access must permit authenticated assets and signed private downloads.

Cloudinary selection does not migrate existing local or S3 files. Each new MongoDB file record includes its provider and Cloudinary public ID; existing records without a provider continue resolving from their existing key format (`applications/...` for S3 and generated UUID filenames for local). Keep any credentials and storage access needed by already-recorded providers until those files are explicitly migrated or retired. Production startup rejects missing MongoDB, weak JWT secrets, wildcard CORS, insecure cookies, local storage, missing S3 buckets, or incomplete credentials for the selected Cloudinary provider.

The Docker image runs as a non-root user, installs `libmagic`, and installs pinned dependencies. Use a production process manager such as Gunicorn with Uvicorn workers; do not use `--reload`. Configure the platform health check to `/api/v1/health/ready`.

Before accepting real customer records, configure and verify Atlas and private storage, review authoritative checklists, configure verified password recovery, decide a malware-scanning approach, test backup restoration, and run the integration/security suite against disposable infrastructure. No live integration or deployment has been verified from this workspace.
